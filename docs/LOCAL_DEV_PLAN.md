# 本地开发环境隔离与旅行助手迁移方案

## 1. 目标与整体结构

采用你已确认的方案：**复用现有 Ubuntu，使用开发容器隔离项目，共享本地 PostgreSQL；休闲时明确关闭整个开发环境。**

| 层次 | 放什么 | 隔离原则 |
| --- | --- | --- |
| Windows | 日常软件、游戏、浏览器、VS Code、Docker Desktop | 不再全局安装项目运行依赖 |
| 现有 Ubuntu 24.04 | Git 工作区、基础设施配置、容器管理入口 | 不重装，不清理既有软件 |
| 每个项目的开发容器 | Python、Node、uv、项目依赖、前后端进程 | 不同项目可使用不同版本 |
| 独立 PostgreSQL 容器 | 多个项目的业务数据库与检查点 | 每项目独立数据库、独立账号 |
| 独立备份目录 | 数据库逻辑备份、环境配置备份 | 不随项目容器删除 |

这是**依赖和服务隔离**，不是完全独立的安全沙箱：仍共享电脑硬件，容器能修改明确挂载给它的文件。VS Code 通过 Dev Containers 连接项目环境。[官方说明](https://code.visualstudio.com/docs/devcontainers/containers)

本次同时完成通用环境建设和旅行助手迁移；不部署公网，不购买服务，不改为本地大模型。

## 2. 环境与数据布局

### 保留旧环境，建立新的主工作区

- 复用位于 `D:\WSL_Data` 的 Ubuntu，使用现有用户 `kyle`。
- 在 `/home/kyle/dev` 下划分 `projects`、`infra`、`config`，分别存项目代码、共享服务配置和不进 Git 的凭据。
- 旅行助手在 Linux 工作区重新检出；原 Windows 项目目录完整保留，迁移验收后也不自动删除。
- 不复制 Windows 的 `.venv`、`node_modules`；使用现有锁文件在容器内重新安装。
- 密钥仅迁移到本地受限配置文件，不打印、不写入镜像或 Git。
- Ubuntu 中现有 Ollama 不卸载、不调整模型文件。

代码保存在 Linux 文件系统内，而不是通过 `/mnt/c` 运行大量依赖文件，符合 Docker 的 WSL 开发建议。[官方建议](https://docs.docker.com/desktop/features/wsl/best-practices/)

### 容器与资源

- 沿用现有 Docker Desktop 的 WSL2 后端和 Ubuntu 集成，不再安装第二套 Docker Engine。
- 旅行助手使用一个非 root 开发容器，包含 Python 3.13、Node 24、uv；前后端分别启动，方便调试。
- 初始资源上限：项目容器 4 CPU、6 GiB；PostgreSQL 容器 2 CPU、2 GiB。
- 不修改全局 WSL 内存上限，避免意外限制现有 Ollama；这些容器上限不代表整套 WSL 的总占用上限。
- 不向项目容器挂载整个 Windows 用户目录或 Docker 管理套接字。
- 前端、后端和数据库发布端口仅绑定本机回环地址；默认分别为 5173、8000、15432。端口被占用时报告冲突，不杀其他进程。
- 保留现有网络模式。备份后恢复 WSL 防火墙过滤，验证 Docker、DNS 和本机访问；如需规则，仅增加必要规则，不以关闭整个防火墙解决问题。
- 先核实 Docker 实际数据磁盘位置。若在 C 盘，通过当前版本支持的迁移方式移至 D 盘；迁移前备份，不手工拖动运行中的虚拟磁盘。

## 3. 可供多个项目复用的 PostgreSQL

- 使用 PostgreSQL 17，首次配置时固定具体镜像版本和摘要，不使用浮动 `latest`。
- 数据库属于独立 Compose 项目，不能被旅行助手的停止或重建命令顺带删除。
- 使用命名数据卷保存数据库文件；容器停止或重建后数据仍保留。[数据卷说明](https://docs.docker.com/engine/storage/volumes/)
- 当前项目创建独立数据库和非超级用户账号；业务表、账号表和 LangGraph 检查点均存其中，检查点保留独立 schema。
- 后续项目通过统一初始化脚本创建各自的数据库和账号，撤销不必要的公共连接权限，验证不能跨项目访问。
- 管理员凭据只供维护命令使用，应用不能使用数据库管理员账号。
- PostgreSQL 大版本不自动升级；升级作为独立备份、恢复与兼容性验证任务。

提供三个管理入口：

- **新增项目数据库**：创建数据库和专用账号，不覆盖已有数据库。
- **备份**：使用 `pg_dump`，在正常“结束开发”流程中执行；只在备份成功后轮换旧备份，每库保留最近 14 份。
- **恢复**：默认恢复到新数据库，先验证，不直接覆盖原库。

备份放在 D 盘独立目录。它能防误删，但仍与电脑共用硬盘，**不是硬盘故障级备份**；不自动接入云备份或外部付费服务。

## 4. 旅行助手迁移

### 保留已有能力

保留 Vue、FastAPI、LangGraph、日志、SSE、历史侧栏、编辑保存、导出和 PostgreSQL Checkpointer，不重写规划流程。

调整数据库启动逻辑，使其通过 Docker 网络连接共享 PostgreSQL；前端仍通过后端访问数据，不直接连接数据库。

### 将 Supabase 登录替换为本地账号

- 使用本地邮箱标识＋密码注册登录，不发送验证邮件，不宣称邮箱已验证。
- 移除运行时 Supabase 依赖、GitHub 登录入口及相关环境变量要求。
- 密码使用 Argon2id 哈希；账号和会话保存在当前项目数据库。
- 使用随机、不透明的会话令牌；数据库只保存令牌哈希。浏览器通过 HttpOnly、SameSite Cookie 携带会话，本地 HTTP 不强制 Secure。
- 会话有效期 7 天，退出立即撤销；所有修改请求执行来源检查和 CSRF 防护。
- 登录失败统一提示，不暴露账号是否存在；增加登录尝试限速。
- 不提供默认密码或匿名鉴权绕过。

新增接口：

| 接口 | 用途 |
| --- | --- |
| `POST /api/auth/register` | 注册并建立本地会话 |
| `POST /api/auth/login` | 登录 |
| `GET /api/auth/session` | 返回当前用户、会话状态和 CSRF 信息 |
| `POST /api/auth/logout` | 撤销当前会话 |

现有行程接口路径保持不变，只更换认证方式。SSE 使用会话 Cookie，保留事件重放；会话过期后要求重新登录，不重新提交规划任务。

当前没有已配置的 Supabase 数据源，本轮按新建本地账号和数据库处理；不导入、不删除任何远程数据。模型、高德等外部服务配置保留，仍可能需要联网和产生 API 费用。

## 5. 日常操作、验收与交付

### 开发与休闲切换

提供清晰的脚本和教程，区分：

- **开始开发**：启动 Docker、检查数据库健康、打开项目开发容器；前后端通过明确任务启动。
- **只关闭旅行助手**：停止该项目，不影响共享数据库及其他项目。
- **结束全部开发**：列出运行中的容器、规划任务和 WSL 发行版，确认后备份数据库、正常停止服务、退出 Docker，最后关闭全部 WSL。

最后一种操作会同时停止已有 Ollama 和其他 WSL 任务，必须每次明确确认，不绑定到关闭浏览器或 VS Code。备份失败时暂停流程并提示，不静默忽略。整个流程不删除数据卷，不执行全局清理。

### 验收标准

- Windows 无新增全局 Python、Node 或 PostgreSQL 服务；原项目目录和既有 Ubuntu 内容保留。
- 在开发容器内能够安装锁定依赖、启动前后端、运行测试和构建。
- 使用真实本地 PostgreSQL 验证注册、登录、退出、账号隔离、历史编辑和检查点恢复。
- 重建项目容器、重建数据库容器并重新挂载原数据卷后，账号与历史仍存在。
- 用第二个测试项目验证数据库复用与权限隔离；停止旅行助手不影响第二个项目。
- 完成一次备份到新数据库的恢复演练。
- 验证 SSE 断线重连不重复提交任务，后端中断后可以手动恢复。
- 全部开发环境关闭后相关端口不可访问；重新启动后数据正常。
- 自动化联调使用模拟模型和地图响应，不自动消耗真实 API 额度；真实行程由用户主动提交验收。

交付开发容器配置、共享数据库模板、启停与备份脚本、本地认证改造及中文操作教程。项目配置与关键修改分模块提交 GitHub；个人凭据、数据库文件、备份和机器专属设置不提交。
