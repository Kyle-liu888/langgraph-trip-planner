# 旅行手账界面

## 设计依据

本轮使用 [Anthropic frontend-design Skill](https://github.com/anthropics/skills/tree/main/skills/frontend-design) 指导设计。Skill 安装在本机 Codex 技能目录，不属于项目运行依赖；项目没有增加 npm 包、远程字体或背景图片。

界面的核心用途是填写旅行需求、查看真实规划状态和管理已有行程。初始「旅行杂志」方向经过审视后，改为更贴合操作场景的「旅行手账」：用路线插图作为唯一装饰重点，而不是照片横幅、英文标签和重复的数字卡片。路线图是虚构装饰，不表示真实目的地或可执行路线。

## 视觉约定

| 色彩 | 值 | 用途 |
| --- | --- | --- |
| 纸面 | #f7f9f6 | 页面背景 |
| 白色 | #ffffff | 内容与输入区域 |
| 墨色 | #203c38 | 正文、深色历史侧栏 |
| 辅助文字 | #5f726d | 说明、日期、次要文字 |
| 深青 | #176b5b | 操作、选中状态、路线图 |
| 浅绿 | #c7df9b | 侧栏新增按钮、图标点缀 |

正文使用 Segoe UI / Microsoft YaHei / PingFang SC 系统字体；主要标题使用 STKaiti / KaiTi / Noto Serif CJK SC 回退栈，呼应手账题字。没有字体下载请求，系统间字形可能不同。

全局色彩和可访问性样式见 `frontend/src/styles/theme.css`，Ant Design 主题见同目录 `theme.ts`，调整时同步两处。辅助文字已根据浅色背景加深。保留可见键盘焦点，并尊重 reduced-motion 设置。

## 布局与边界

整体左对齐；登录页表单垂直居中。比较过保留双侧栏与横向章节导航，后者为景点图片和来源说明留出更多空间，因此采用：

```text
桌面：历史侧栏（248px） | 页面标题
                       | 需求表单 / 行程状态
                       | 横向章节与日期导航（结果页）
                       | 概览、预算与地图
                       | 每日行程、景点及核验入口

手机：菜单按钮 + 页面标题
      单列表单 / 行程内容
      历史记录放入抽屉，章节导航可横向滚动
```

首页的地图路线插图在手机上隐藏，避免挤压表单。登录页手机插图隐藏，避免覆盖文字。

完成状态使用简短说明，原始生成结果、节点事件、连接信息与运行编号仍保存在可展开的「规划记录」中。失败恢复按钮和 API 费用说明直接显示，未更改任务/SSE 行为。

## 保留的能力

- 认证、注册校验、退出与历史记录操作。
- 规划表单的数据和提交协议、用量与费用提示。
- 真实进度、检查点恢复、图片、地图、编辑保存和导出。
- 景点来源、查询与核验日期、门票预算估算、官方入口和攻略搜索。

未改后端、数据库、模型调用或规划流程。首页不再加载原先的 Unsplash 背景图；景点图片依旧沿用现有高德逻辑。

## 验证

在项目开发容器的 `/workspace/frontend` 中运行：

```bash
npm test
npm run build
```

新增页面级模拟测试覆盖：首页展示、偏好选择、人数联动、缺失字段校验；登录模式切换；历史选中和导航操作；结果章节导航、编辑取消；完成记录、真实节点和失败恢复。自动化测试不调用模型和地图服务。

浏览器检查使用已有行程，不创建新的规划任务；检查登录/注册切换、桌面布局、手机历史抽屉以及旧行程展示。地图与景点图片沿用普通页面加载请求，不新增付费数据源。

2026-09-06 验收：47 项前端测试通过，类型检查与生产构建通过。实测 1280px 桌面与 390px 手机布局，日期导航展开对应行程、编辑/取消、键盘回到顶部正常。构建仍提示已有大型 JavaScript 分块，本轮未改变打包策略。
