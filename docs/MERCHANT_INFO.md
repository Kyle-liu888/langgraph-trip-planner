# 餐饮与住宿门店资料卡

## 用户能看到什么

打开已有行程并展开某一天，餐饮和住宿卡片会异步核验门店，展示可获取的地址、高德地图入口、参考评分、最多三张参考图片，以及餐饮特色。无需重新规划，也不需要额外填写平台账号。

卡片标题旁的问号可查看预算边界、完整来源与查询时间、图片说明、人工核验日期和搜索使用说明。默认保留“预算估算”“高德参考评分”、地址核验状态、简短失败提示及操作按钮，不逐段重复免责声明。问号支持点击、键盘和触屏；可按 Escape、点击关闭或点击外部收起。复制失败时搜索词会直接显示，便于手动复制。导出图片/PDF保留这些关键标识，但不绘制不可交互的问号和说明浮层。

这些资料只是结果页的补充，不参与生成、排序、预算或检查点，不调用模型、不回写历史。高德人均消费不是房价；卡片原有餐饮、住宿金额仍是预算估算，零估算也不代表免费。没有可追溯来源的旧酒店评分不再展示为可信评分。照片没有可靠分类时只称“门店参考图”，不推断成招牌菜或客房实拍。

“保存修改”仍会保存用户对行程的编辑；门店补充资料不会加入保存请求。

门店外链与小红书搜索分开：

| 类型 | 核验过的具体门店链接，缺少就省略 | 搜索入口 |
| --- | --- | --- |
| 餐饮 | 高德、大众点评、美团 | 小红书搜这家店：城市＋完整分店名＋探店 |
| 住宿 | 高德、携程、美团 | 小红书搜这家酒店：城市＋完整分店名＋住宿体验 |

搜索页不是已核验攻略，不保证搜索结果对应同一家店。平台可能要求登录或验证，用户可以复制搜索词自行查询；不改跳百度，也不把首页当店铺来源。不抓取评论或平台图库，不生成评价总结，不执行预约或支付。“酒店早餐”“酒店自助早餐”“当地小吃”等泛称只是安排说明，不会强行匹配门店，也不表示酒店房费包含早餐。

## 查询与身份核验

登录保护的 `GET /api/poi/merchant-info` 接收 `kind=food|hotel`、`city`、`name`，以及可选的 `address`、`poi_id`、成对的 `longitude` / `latitude`。返回 `{success, data}`；`data` 是独立的门店资料对象，而不是 `TripPlan` 的新字段：

- `match_status`：`matched` / `unmatched` / `ambiguous` / `insufficient` / `generic`。
- `data_status`：`available` / `no_data` / `permission_denied` / `timeout` / `unavailable`。
- `place`：已匹配的 POI ID、名称、城市、地址和可用坐标；`source`：高德来源名称、地点入口、查询时间。
- `photos`、`rating`、`food_tags`：只包含实际获取到的可用参考字段。
- `links`：人工核验的平台详情 URL、平台、按钮文案及 `verified_at`；`queried_at` 和 `message` 说明本次查询时间与状态。

名称规范化只处理空白和括号形式，不删除分店名。城市、完整名称和餐饮/住宿类型必须一致；提供的 POI ID、地址或坐标互相矛盾时拒绝匹配。没有 POI ID 时还需具体地址或坐标佐证，并要求唯一结果；坐标距离上限为 500 米，不能单凭“附近有一家同品牌”认定同店。

现有高德 v3 查询核验基础身份，v5 地点详情获取 `business,photos`。v5 无权限或超时仍可保留已经核验的基础地址和地图入口；人工登记链接能独立匹配分店时，也不依赖实时高级字段成功。明确身份冲突时不展示链接。旧行程坐标不因已经存在就自动成为可靠事实；前端原先“取第一条搜索结果补坐标”的行为改为核验后的独立地图补充，不改写保存对象。

HTTP 单次超时 8 秒，不自动重试，复用现有高德进程内限速；成功和确定性空结果缓存 15 分钟、最多 512 条，临时上游故障不缓存。前端最多 3 个并发请求，同一身份跨天复用；编辑名称、地址或坐标后丢弃旧响应并重新匹配。资料查询失败不阻塞地图、行程与搜索入口；登录失效仍按原账号流程重新登录，不提供匿名绕过。

日志事件 `poi.merchant_info_resolved` 记录类别、匹配状态、资料状态、缓存命中和耗时；失败日志只记录错误类型，不记录密钥或带密钥的 HTTP 地址。默认不会输出整份商家资料。

## 如何新增或维护平台链接

文件：`backend/app/services/merchant_sources.json`。这是人工维护的小规模登记表，**不是全国门店检索库**。高德图片、评分不要求门店先进入登记表；大众点评、美团和携程按钮则只有收录且身份匹配后才出现。

1. 从平台公开详情页确认城市、完整名称、分店和具体地址，再与高德地点核对。不要仅依据搜索摘要、品牌名或模型生成内容登记。
2. 填写 `kind`、`city`、`name`、`address`、`poi_ids`、`location`。`poi_ids` 是高德 ID，不能推算其他平台 ID；无可靠坐标可用 `null`，但必须保留足够的分店证据。
3. 在 `links` 中填写 `platform`（`dianping` / `meituan` / `ctrip`）、公开详情 `url` 和实际人工核验当天的 `verified_at`（`YYYY-MM-DD`）。餐饮不登记携程、住宿不登记点评。
4. 在真实浏览器打开链接，检查最终页面。短链需核对最终详情地址；落到通用搜索或首页就不收录。仅登录门槛且保留精确目标的链接需要另有公开页面证明身份，并注明访问限制。
5. 只允许对应平台域名的 HTTP/HTTPS 详情链接。服务端不会抓取这些外链；不要填登录页、验证码页、私有地址或含 token、Cookie、密码、会话参数的分享链接。新增地址形式需更新后端 URL 校验和测试，不能扩大为任意网址。
6. 重启后端让登记表缓存失效，运行后端 `test_merchant_info.py` 与前端门店测试，再打开匹配行程检查。更改凭据不是本功能的维护步骤。
7. 链接失效时移除对应链接，或将整个条目的 `enabled` 设为 `false`。重新核验后才更新日期；刷新页面不会更新人工日期。首期没有自动过期天数或后台定时复查，所以历史核验不保证永久有效。

最小结构示意（请从已收录的真实条目复制结构，不把示意 ID 或网址提交为有效来源）：

```text
items[]
  kind, city, name, address
  poi_ids[]
  location: {longitude, latitude} 或 null
  links[]: {platform, url, verified_at}
  enabled: false（可选，停用整个条目）
```

维护者只需用户提供的城市＋完整分店名／地址，或公开商家分享链接，不需要个人平台密码、Cookie 或新增服务采购。继续沿用高德现有授权与额度；本功能不承诺现有调用免费，不会自动购买高级字段权限。
